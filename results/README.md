# Audited result artifact

This directory contains the audited raw outputs and derived tables. Raw
per-model files are the canonical inputs to the derived tables. “Gold” here
means that identities, provenance, coverage, and transformations are checked;
it does not make a historical implementation or statistical choice
scientifically authoritative.

The sentence configurations are complete datasets. In particular, the archived
and corrected RACE grids both contain all 4,934 prompt IDs; the old/new row-count
difference is a prompt-template difference rather than prompt downsampling. The
two word configurations are deterministic samples of exactly 10,000
`(prompt_idx, seg_idx)` pairs under a fixed ablation-coordinate budget. RACE uses the
current punctuation-normalized prompt template for both phases; it must not be
combined with the archived 136,313-row template.

The BoolQ word sample contains 10,000 of 476,154 possible coordinates and
3,028 of 3,270 prompts. The LAMBADA word sample contains 10,000 of 422,134
possible coordinates and 4,387 of 5,153 prompts. Both are the exact seed-42
coordinate samples independently regenerated by the public sampler and found
in the archived snapshot; uncapping them would define a different estimand.


`segments.tsv.gz` is the model-independent coordinate system. Every row
contains `prompt_idx`, `seg_idx`, `message_idx`, `message_role`,
`message_seg_idx`, exact `segment_text`, and `n_segments`. A per-model segment
file must reproduce those identities exactly. `segment_result_available`
distinguishes a scored row from a materialized missing hosted result.
Hosted run sidecars also record the matched prompt and ablated-dialog SHA-256
receipt hash from an exhaustive producer/public identity audit of each grid;
the matched prompt and ablated-dialog SHA-256 digests are stored in that
receipt.

Open-model run sidecars record `attention=eager` and `ablation=sdpa`. The
runner loads a separate model instance for each phase so requesting attention
cannot silently change the ablation backend. `execution_model_source` preserves
the repository locator configured during execution, while `model_source`
records the canonical public repository whose immutable revision and complete
file manifest were checked at sealing time.

Token tables retain raw label/token log-probabilities. Hosted label aggregates
are marked `logprob_granularity=label_aggregate`; labels absent from a top-k
response are represented by `-inf`. Their segment tables separately retain
`original_request_status` and `segment_request_status`, so a successfully
executed call whose requested labels were censored cannot be confused with a
provider content-filter rejection, a retry-exhausted request, or an unclassified
failed call. LAMBADA stores original and ablated
completion log-probabilities in its segment tables instead. Hosted LAMBADA
rows also retain `original_result_status` and `segment_result_status`, so a
successful score, application rejection, unavailable echo response, target
parse miss, non-finite returned score, or canary-based placeholder remains
distinguishable.

## Model cohorts

The primary paper cohort contains 11 models:

- Open: Qwen-2.5 0.5B, 3B, 7B, and 14B Instruct; Llama-3.1-8B Instruct.
- Hosted: Llama-3.1-70B, Llama-3.3-70B, Llama-4 Maverick, GPT-4o, GPT-4.1,
  and Gemini 2.5 Flash Lite.

The hosted Llama-3.1-8B result is preserved as a same-weights/different-serving
diagnostic but excluded from headline 11-model summaries.

## Derived tables

`f_table.tsv` contains the seven paper-era scalar configurations; RACE is
separate because its stated metric is multivariate. `f_table_message_scopes.tsv`
adds all/system/user strata. `f_table_anli_contrasts.tsv` includes
entailment–neutral and entailment–contradiction.
`f_table_prompt_equal_transfer.tsv` preserves the later notebook-source
mean-within-prompt-`r²` transfer statistic as a sensitivity; the PDF transfer
cells in `f_table.tsv` use a global row-pooled correlation.

The two `f_table_revision_candidate_*` files combine the manuscript-intended
user-segment coordinates and ANLI entailment-minus-contradiction direction.
They differ only in treatment of successful hosted responses whose requested
label is absent from top-k: pair-specific deletion versus finite-extreme
replacement. Both carry `artifact_role=revision_candidate` and
`selection_status=author_decision_required`; neither is silently designated as
the revised headline result. Open/open rows are required to agree exactly
between the two candidates.

Every scalar row includes both requested and resolved estimand metadata.
`F_pred` resolves to `prompt_level_full_dialog` and therefore repeats unchanged
across requested message scopes. Segment scopes mean system/user coordinate
filters over executions that retained the full dialog; they do not mean that
the other message was removed from model context. Symmetric `F_attn` and
`F_mag` have `resolved_*_contrast=not_applicable` and repeat unchanged across
requested ANLI contrasts. Attention/magnitude transfer rows record an
uncontrasted source and the contrast-specific attribution target. Because the
stored ANLI readout direction is entailment-minus-neutral, `F_align` and
`F_align_to_attr` rows requested under entailment-minus-contradiction are kept
as explicit unavailable rows with `readout_contrast_mismatch` rather than
being omitted or relabeled.

RACE outputs are deliberately distinct:

- `race_multiclass_open.tsv` is the strict full-coverage corrected-grid
  analysis: signed Frobenius correlation, direction cosine, linear CKA, and
  Aitchison, finite Fisher–Rao, and baseline-local-Fisher magnitude
  correlations, with row-pooled and prompt-equal aggregation.
- `race_multiclass_paper_global_complete_case.tsv` applies those metrics to one
  global complete-case intersection across the 11-model cohort. It is labeled
  MNAR and is a sensitivity analysis.
- `race_rv_open.tsv` is the full-coverage corrected-grid centered-RV analysis.
- `race_rv_paper_complete_case.tsv` extends it to the 11-model cohort using the
  paper Figure 13 pair-specific top-k complete-case policy and reports coverage.
- `race_scalar_paper_compatibility.tsv` applies the answer-conditioned legacy
  scalar estimand to the corrected grid. It does not reproduce the historical
  `.462/.524` values unless evaluated on the archived 136,313-row grid.

Filter `representation=all_pairs` for the stated six-dimensional A–D metric;
`representation=anchor_a` is included as a three-dimensional sensitivity view.

`coverage.tsv` records original-prompt, marginal ablated-segment, paired
attribution, and label-cell coverage for every model/configuration. For hosted
classification runs it also reports separate original- and ablated-request
content-filter counts, so provider filtering is not folded into top-k label
censoring. Consult it
instead of inferring completeness from file existence.

Every derived TSV has a neighboring `.provenance.json` sidecar. It binds the
table to the complete shipped raw-input set, public generator and preparation
sources, model cohort, missingness policy, bootstrap seed/count, confidence
level, and numerical-library versions. The release validator verifies these
bindings and the top-level artifact manifest without rewriting either one.
`hosted_classification_audit_receipt.json` additionally binds all 49 hosted
classification cells to their raw-payload hashes, public response projections,
request-status counts, prompt/ablation identity digests, and an opaque digest of
selected producer/audit source files at finalization. The identity digests come
from an exhaustive post-run reproduction that independently compares the
producer and public prompt builders and ablated dialogs. The source digest is a
finalization-time snapshot, not proof that those exact bytes executed for every
request. It contains no service implementation, routing aliases, or private
paths. The receipt seals the audited final state; provider-specific per-attempt
transcripts were not retained, so it does not attest historical retry counts or
intermediate retry rounds.
`hosted_completion_audit_receipt.json` analogously binds all seven hosted
LAMBADA cells. Four entries seal the entire fixed sampled-manifest population
(4,387 prompts and 10,000 coordinates, not all 5,153 source prompts or 422,134
possible coordinates) and require their raw and public projections to match exactly.
Three entries seal the fixed 10-prompt/823-segment canary separately from the
all-missing 10,000-row public placeholder. It records both populations'
coordinate, prompt, target, and full ablated-dialog identities, plus raw/public
availability counts. This prevents a placeholder from being justified by an
unrelated canary while preserving the distinction between unsupported current
endpoints and historical sparse archive measurements.
When `validate_results` is given `--dataset-dir`, it regenerates all public-side
dialog digests from the frozen datasets and manifests before accepting them,
including both LAMBADA completion populations.

`open_execution_audit_receipt.json` preserves the exact 5-model ×
8-configuration numerical-audit grid. It binds each verdict to the producer
segment, token, manifest, and pre-seal run-metadata bytes, then separately
binds the normalized release segment bytes and their complete substantive
projection. The recorded public normalization adds only explicit availability
columns; this is transparent operational evidence, not a claimed
cryptographic pre/post equivalence proof. Four source hashes were written into
every run at completion. The receipt additionally records
the hashes and pre-queue modification times of all ten public modules imported
by the execution path. Complete weight hashes were computed at sealing time, so
the timestamp evidence is explicitly corroborating rather than a retrospective
start-time cryptographic seal. Archive correlations are labeled
`historical_replication_diagnostic_not_scientific_correctness`: they guard
against unexplained execution drift but do not make the archived implementation
or estimand authoritative.

The Qwen-2.5-0.5B BoolQ-word attribution comparison is deliberately labeled
`new_artifact_not_archive_equivalence`: its pooled current/archive correlation
is `.935890002` (system `.970071098`, user `.861215557`). An exact SDPA repeat
reproduced the current output, whereas an eager-backend check was worse
(`r = .877541610`). Across all four peer models and all/system/user strata,
substituting the corrected values changed pairwise Pearson `r²` by at most
`.011718002` and prompt-level Spearman by at most `.014875454`. These are
sensitivity bounds, not evidence that the historical values were correct; the
remaining historical cause is unresolved.
`open_attention_replay_receipt.json` records a separate attention execution on the full
476,154-coordinate, 3,270-prompt BoolQ-word corpus for each Qwen model. It
requires all three corrected attention variants on the fixed 10,000-coordinate
release sample to match at Pearson `r >= 0.999999` and maximum absolute error
at most `1e-7`; the release sample itself contains 3,028 prompts. The receipt
also pins the frozen BoolQ dataset, canonical full-manifest bytes, and eager
attention backend, so the 466,154 non-release coordinates are externally
anchored rather than merely self-consistent.

The `reconciliation/` artifact is optional for exploratory runs but mandatory
and included in the audited release. It is produced by
`python -m benchmark_scripts.reconcile_results`. It recomputes the printed
Table 1 and Table 2 scalar cells from separately supplied legacy wide TSVs and
places them beside corrected results without conflating estimands. Its external
legacy model map is required so archive-only routing aliases never enter the
public code or emitted ledger. The reconciliation manifest uses logical
locators and hashes only; the checks file verifies row-count/publication
sentinels and corrected provenance sidecars. Its archive hashes pin the raw
Archived snapshot bytes rather than a normalized Drive export; canonical
digests additionally pin every sanitized archive ledger row and audit check.
Because the exact PDF bytes and arXiv version were unavailable during this
audit, the manifest marks the manuscript reference
`unversioned_reference_not_byte_pinned` and separately hashes the immutable
transcription of the audited claims. `manuscript_disposition.tsv` records each
known issue and whether it should be retained, clarified, replaced, disclosed,
or left for an author decision. A numerical match to the archive is recorded
separately from whether the manuscript's metric description was correct.
The six historical BoolQ-word attention and attention-to-attribution rows carry
an explicit `*_invalid_sentence_attention_contamination` data status and a
different segment-grid ID from their corrected word-level counterparts.
`historical_claims.tsv` separately recomputes selected numerical sensitivity and
provenance claims outside the Table 1/2 cells, including RACE Figure 13 and
expanded multiclass summaries, prompt-grid skew, main-text examples,
finite-extreme sensitivity, the later prompt-equal transfer statistic, and the
BoolQ-word Qwen sentence-attention contamination invariant. It also checks the
prompt-version-independent RACE readout norm exactly across all 4,934 prompts
for each of the five open models. Its
RACE computations are bound to the eleven raw archived four-label JSON files;
the scalar consolidated RACE TSV alone cannot recover those estimands.
For the two Figure 13 median claims, `n_observations` is the sum of the 55
pair-specific complete-case counts, not a shared sample size; `effective_pairs`
identifies that pair set.
Claims use an explicit `expected_relation`: normally `within_tolerance`, or
`outside_tolerance` when the audited fact is that a printed value does not
reproduce. This keeps known discrepancies visible without making a faithful
reconciliation fail by construction.
The archive input directory must therefore contain those eleven JSONs in
`race_raw/{public-model-id}.json` (legacy snapshot basenames are also accepted
on input); emitted locators always use the neutral public-model form.
RACE contains
only the two scalar Table 2 cells actually printed (`F_pred` and `F_attr`), and
its historical and corrected segment grids remain non-comparable.
Reconciliation requires a single known `aggregation` value per corrected cell;
`row_pooled` matches the PDF, whereas `prompt_equal_mean_r2` is recorded as a
nonmatching sensitivity. A failed required check makes the command exit nonzero
after writing diagnostics.

A hosted LAMBADA run labeled `complete` must reach at least 80% original,
marginal ablation, and paired attribution coverage. Classification runs are
accepted when the full coordinate grid was attempted. A run with only successful
and confirmed content-filter responses is labeled `complete`; a run with a
still-missing response after the full retry audit is labeled
`complete_with_terminal_failures`. Unclassified failures are rejected. For
successful responses, requested labels absent from top-k are `-inf`; when no
valid response exists, the result is unavailable and its derived score is
`NaN`. Classification requests set `max_tokens=1`,
`top_logprobs=19`, and `echo=false`. Top-k label
censoring remains explicit and is not conflated with request completion. Their
pairwise estimates use finite complete cases and report `n_obs`, `n_prompts`,
and coverage rather than applying an ahistorical 80% cutoff. LAMBADA uses teacher-forced echo
scoring (`echo=true`, `max_tokens=0`) and sums the returned log-probabilities
for the exact target suffix. Some endpoints do not expose parseable echoed
target scores under the `top_logprobs=20` response contract; that missingness
is endpoint- and prompt-dependent, not evidence that a model is generally
unavailable.

The corrected GPT-4o RACE run retains 110 retry-exhausted ablation coordinates
out of 145,544 (0.076%) as unavailable. The corrected GPT-4.1 RACE run retains
890 retry-exhausted ablation coordinates (0.612%), 1,303 provider-filtered
ablation coordinates, and 47 provider-filtered original prompts. Responses
obtained under a different top-k request are not substituted into the top-19
gold artifact because they would change the measurement protocol.
Endpoints below the relevant threshold are represented in the active corrected
artifact by canonical all-missing rows labeled `unsupported_after_canary`, with
a hashed 10-prompt canary selected by
sorted NumPy `default_rng(42)` sampling without replacement from all 5,153 rows
of the frozen LAMBADA dataset. The audited prompt IDs, answers, and full-dialog
segment counts are fixed in `benchmark_scripts/hosted_completion.py`. Canary ablation
coverage uses all 823 canonical segments as its denominator, including missing
scores. Historical sparse hosted scores remain exclusively in the pinned
paper-era archive used by `reconciliation/`; they are not reused as corrected
measurements. Unavailable pair estimates remain explicit `NaN` rows rather
than disappearing from the expected model-pair grid.

Hosted missing-value policies are explicit. The canonical scalar table and RV
table use the pair-specific finite-row deletion that produced the published
numbers. `f_table_finite_extreme_sensitivity.tsv` instead applies the model-
specific finite-extreme replacement described in the paper's prose. For
attribution, that sensitivity clamps the derived original-minus-ablated signal,
not the two component log-odds columns independently. Counts and coverage are
reported so these policies remain visible.

## Reproduction

Place the separately distributed frozen TSV snapshots named by
`benchmark_scripts/run_all_benchmarks.sh` in one directory, ensure the five
model snapshots are available under `/tmp/models`, then run the open-model
stage:

```bash
DATASET_DIR=/path/to/frozen-tsvs \
RESULTS_DIR=results/rerun \
bash benchmark_scripts/run_all_benchmarks.sh
```

The batch script refuses a nonempty output directory unless `ALLOW_RESUME=1`
is explicit. A non-gold run against live dataset revisions requires
`ALLOW_LIVE_DATASETS=1`. `download_all.sh` fetches the upstream datasets but
does not claim to recreate the byte-identical frozen TSV snapshots; the hashes
above are the authority for a gold run.

Gold open-model snapshots are revision-pinned in `download_all.sh`. Every run
sidecar records the canonical public repository and immutable revision, the
complete selected artifact hash map, and its canonical aggregate digest. The
release validator requires those identities to agree across all eight cells for
each model and with the trusted constants in
`benchmark_scripts/provenance_sources.py`.

Hosted generation is intentionally outside this public repository. Portable
hosted JSON can be imported with `benchmark_scripts.import_hosted_results`, and
legacy TSVs require an explicit segment-identity attestation during
normalization and provenance recording. After importing every hosted result,
rerun the consolidation and derived-table commands in the main README, then run
`benchmark_scripts.reconcile_results` against the pinned historical archive.
The first strict validation seals the complete file inventory; the second
verifies it without mutation:

```bash
python -m benchmark_scripts.validate_results --results-dir results --cohort paper \
    --require-derived --skip-manifest
python -m benchmark_scripts.reconcile_results \
    --archive-dir /path/to/legacy-wide-tsvs \
    --corrected-results-dir results \
    --output-dir results/reconciliation
python -m benchmark_scripts.validate_results --results-dir results --cohort paper \
    --require-derived --require-reconciliation
python -m benchmark_scripts.validate_results --results-dir results --cohort paper \
    --require-derived --require-reconciliation --verify-manifest
```

The validator checks the exact frozen manifest hashes, complete model grids,
segment identity, open-model payload completeness, recorded missingness, and
provenance/output hashes. In release-verification mode it verifies the existing
`coverage.tsv` and `artifact_manifest.json` without rewriting either one.
